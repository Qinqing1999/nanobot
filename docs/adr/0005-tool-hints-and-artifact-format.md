# 工具提示脱敏与制品通知 Markdown 格式

## 状态
已接受

## 背景
工具提示（tool hints）此前将原始命令和文件路径推送给用户（如 `$ pip show n.`、`read /home/user/nanobot.py`），这些诊断性信息对终端用户没有价值，且暴露了内部路径结构。

制品通知此前使用纯文本格式（`1001 [图片] cat.png | 10:01:03`），在支持 Markdown 渲染的通道上缺乏视觉重点，用户难以快速定位制品 ID。

## 决策

### 1. 工具提示仅显示通用标签
`format_tool_hints` 改为返回中文通用描述（如"执行命令"、"读取文件"），不暴露任何参数、路径或命令文本。未知工具仅显示工具名。MCP 工具显示 `server::tool` 格式。所有通道统一行为。

### 2. 制品通知采用 Markdown 格式
所有面向用户的消息中，键值对字段统一使用 `**KEY**: \`VALUE\`` 格式。包括：
- 制品通知：`**制品 ID**: \`1001\` | **类型**: \`图片\` | **文件名**: \`cat.png\``
- 视频完成推送：`**时长**: \`10秒\``、`**分辨率**: \`1280x768\``、`**制品 ID**: \`2001\``
- 任务 ID 等：`**任务 ID**: \`video_abc123\``

### 3. check_video 工具结果不暴露视频 URL
`check_video` 工具返回给 LLM 的结果不再包含 `视频 URL` 字段。LLM 只看到状态和进度，视频文件通过 `OutboundMessage.media` 直接推送给用户，URL 不经过 LLM。

## 考虑过的替代方案

- **按工具类型选择性显示参数**：如 `exec` 显示首词（`pip`）、`read_file` 显示文件名而非完整路径。增加复杂度且首词仍可能暴露敏感信息。已放弃。
- **仅对诊断命令脱敏**：需要分类哪些命令是诊断性的，维护成本高且分类不可靠。已放弃。

## 后果

- `tool_hints.py` 不再导入 `abbreviate_path` 和 `re` 模块。
- 测试文件 `test_tool_hint.py` 完全重写以匹配新的标签行为。
- `format_artifact_notification` 不再包含时间戳。
- 未来新增工具需在 `_TOOL_LABELS` 中注册中文标签，否则回退为工具名。
