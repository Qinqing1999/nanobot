# 制品注册表：Session 级别四位数字 ID 系统

## 状态
已接受

## 背景
nanobot 原有的媒体处理系统中，用户上传的文件和生成的图片/视频只有本地文件路径，没有稳定的可引用 ID。用户上传多张图片后无法指定哪张做参考图、哪张做背景图；生成的图片在后续对话轮次中也无法被引用。

## 决策

新建独立的制品注册表（Artifact Registry），作为 session 级别的基础设施：

1. **ID 方案**：四位纯数字，首位为类型前缀（0=文档，1=图片，2=视频，3=音频）。每个类型在 session 内独立递增编号。
2. **生命周期**：绑定于 session，会话结束（`/new` 或 TTL 过期）时清理。
3. **注册时机**：用户上传文件时在 channel `_handle_message` 中注册；生成图片/视频时在工具结果中注册。
4. **Agent 上下文**：每次 turn 开始时，将当前 session 的 artifact 列表注入 agent 上下文。

## 考虑过的替代方案

- **UUID/哈希 ID**：全局唯一但不可读、不可记忆。四位数字简洁、用户可口头引用。
- **跨 session 持久化**：增加了存储管理复杂度，且大多数使用场景在当前对话内完成。
- **嵌入视频生成 PR 中一起做**：PR 过大、review 困难、影响范围不清晰。

## 后果

- 所有 channel 的 `_handle_message` 需要修改以注册上传文件。
- `InboundMessage` 需要携带 artifact 元数据。
- Agent 上下文构建需要注入 artifact 列表。
- 图像生成工具和视频生成工具都需要在结果中注册 artifact。
